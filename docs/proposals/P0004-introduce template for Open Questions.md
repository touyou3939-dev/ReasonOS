## Purpose

Define the standard template for recording Open Questions.

---

## Proposed Change

Create `docs/templates/Open Question.md` with the following structure.

### Status

Default status is **Open**.

### Question

State the unresolved question clearly.

The question should be concise, objective, and independent of any proposed solution.

### Background

Describe the context that led to this question.

### Why It Matters

Explain why resolving this question is important for ReasonOS.

### Current Understanding

Summarize what is currently known.

Do not include assumptions or unsupported conclusions.

### Possible Directions

List candidate directions without selecting one.

- Option A
- Option B
- Option C

### Resolution Criteria

Describe what would allow this question to be considered resolved.

Examples:

- A design principle is established.
- A responsibility becomes unambiguous.
- Experimental evidence supports one option.

### Related Documents

- Current Understanding
- Development Process
- Commit Proposal
- Other

### Notes

Additional observations.

---

## Rationale

Open Questions should be recorded using a consistent structure.

Questions should be concise, objective, and independent of any proposed solution to avoid biasing future design decisions.
