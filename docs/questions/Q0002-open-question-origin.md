# Question

Should every accepted design change originate from an Open Question?

---

# Background

ReasonOS currently evolves through discussion, commit proposals, and updates to Current Understanding.

During recent development, some design changes naturally emerged from explicit questions, while others arose directly from discussion.

It is currently unclear whether every accepted design change should first be represented as an Open Question, or whether some changes can proceed without one.

---

# Why It Matters

This decision will define the standard development workflow of ReasonOS.

If every accepted change requires an Open Question, the process becomes more explicit and traceable.

If exceptions are allowed, the process may remain simpler and more efficient.

The balance between discipline and flexibility has not yet been determined.

---

# Current Understanding

No accepted rule currently exists.

---

# Possible Directions

- Every accepted design change should begin as an Open Question.
- Only significant architectural changes require an Open Question.
- Open Questions are optional and created only when clarification is needed.
- Another workflow may better support the evolution of ReasonOS.

---

# Resolution Criteria

This question can be resolved when the development process has been exercised sufficiently to determine whether requiring an Open Question improves the quality and maintainability of ReasonOS.
